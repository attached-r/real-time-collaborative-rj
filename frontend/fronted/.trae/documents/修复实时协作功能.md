# 实时协作功能修复计划

## 问题分析

通过分析前端和后端代码，我发现了以下关键问题导致实时协作不生效：

### 1. 消息目的地不匹配
- **前端发送**：`/app/edit/${docId}`
- **后端接收**：`/document/${docId}/delta`
- **前端订阅**：`/topic/${docId}`
- **后端广播**：`/topic/${docId}/content`

### 2. 消息格式不一致
- **前端发送**：纯文本字符串
- **后端期望**：包含 delta 信息的结构化消息

### 3. 缺少用户身份信息
- **前端**：发送消息时未包含发送者信息
- **后端**：需要发送者信息以排除自己接收广播

### 4. 在线用户列表请求目的地不匹配
- **前端请求**：`/app/online/${docId}`
- **后端**：可能缺少对应处理方法

## 修复方案

### 前端修复（EditDocumentView.vue）

1. **修正消息发送目的地**
   - 将发送目的地从 `/app/edit/${docId}` 改为 `/app/document/${docId}/delta`

2. **修正消息订阅目的地**
   - 将订阅目的地从 `/topic/${docId}` 改为 `/topic/${docId}/content`

3. **统一消息格式**
   - 发送消息时包含发送者信息和内容
   - 格式：`{ sender: currentUsername, content: fullText }`

4. **修正在线用户列表请求**
   - 检查后端是否有对应的 `/app/online/${docId}` 处理方法
   - 如无，调整为后端支持的格式

5. **优化错误处理和日志**
   - 增加 WebSocket 连接和消息发送的错误处理
   - 优化日志输出，便于调试

### 后端验证（可选）

1. **确认后端消息处理逻辑**
   - 验证 `/app/document/{docId}/delta` 端点是否正确处理消息
   - 验证 `/topic/{docId}/content` 广播是否正常

2. **确认在线用户列表处理**
   - 验证 `/app/online/{docId}` 端点是否存在
   - 如不存在，考虑添加或调整前端请求格式

## 预期效果

修复后，当用户 A 编辑文档时，用户 B 将会：

1. 实时看到用户 A 的编辑内容
2. 正确显示在线用户列表
3. 不会收到自己发送的编辑广播（避免重复更新）

## 验证步骤

1. 启动前端和后端服务
2. 打开两个浏览器窗口，登录不同用户
3. 同时编辑同一文档
4. 验证编辑内容是否实时同步
5. 验证在线用户列表是否正确显示
6. 验证编辑操作是否不会触发自己的界面更新

## 注意事项

- 确保 WebSocket 连接正常（检查浏览器控制台和后端日志）
- 确保 JWT token 有效，能够通过 WebSocket 认证
- 确保文档 ID 正确传递和处理
- 注意消息格式的一致性，避免解析错误

通过以上修复，实时协作功能应该能够正常工作，实现多用户同时编辑文档的实时同步效果。
